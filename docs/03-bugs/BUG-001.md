# BUG-001 — Subtotal de exatamente R$ 200,00 cobra frete (deveria ser grátis)

| Campo | Valor |
|-------|-------|
| Severidade | Alta |
| Prioridade | Alta |
| Impacto no negócio | O cliente que fecha o carrinho em exatamente R$ 200,00 paga R$ 19,90 a mais do que a promessa de frete grátis. A tela ainda mostra "Faltam R$ 0,00", o que confunde e gera reclamação. |
| Camada | API e UI (a UI exibe o que a API calcula) |
| Critério violado | **CA06** (frete grátis "a partir de R$ 200,00, **inclusive**") |
| Ambiente | https://verzel-store.qa-test-verzel-store.workers.dev/ — v2.3.0, Chromium 156 / Windows 11 |
| Cenários relacionados | CT-016, CT-020 |

## Passos para reproduzir (UI)
1. Na vitrine, adicionar 1x **Mochila Urbana 20L** (R$ 100,00).
2. Adicionar 2x **Garrafa Térmica 750ml** (R$ 50,00 cada).
3. Abrir o **Carrinho**.

## Passos para reproduzir (API)
```http
POST /api/carrinho/calcular
{"itens":[{"produtoId":"P005","quantidade":1},{"produtoId":"P008","quantidade":2}]}
```

## Resultado esperado
Subtotal R$ 200,00 → **frete R$ 0,00 (grátis)**, `freteGratis: true`, total R$ 200,00. Sem aviso de valor faltante.

## Resultado obtido
- Subtotal R$ 200,00, **frete R$ 19,90**, total **R$ 219,90**.
- API: `"frete": 19.9, "freteGratis": false, "valorFaltanteFreteGratis": 0`.
- A UI exibe o texto incoerente **"Faltam R$ 0,00 para o frete grátis."**.
- O mesmo ocorre em `POST /api/pedidos` (pedido confirmado com frete cobrado).
- Com o cupom BEMVINDO10 (CT-020): total R$ 199,90 em vez de R$ 180,00.

## Observações / hipótese
Subtotais de R$ 199,80 e R$ 199,90 (abaixo) e R$ 209,90 (acima) se comportam corretamente: o problema está só na borda. A condição provavelmente usa `subtotal > 200` em vez de `subtotal >= 200`. Os dois valores `valorFaltanteFreteGratis: 0` e `freteGratis: false` ao mesmo tempo mostram a contradição.
