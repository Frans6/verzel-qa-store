# BUG-004 — Item sem `produtoId` gera "Produto undefined não encontrado" em vez de `ITEM_INVALIDO`

| Campo | Valor |
|-------|-------|
| Severidade | Baixa |
| Prioridade | Baixa |
| Impacto no negócio | Quem integra com a API recebe um erro confuso ("Produto undefined não encontrado.") e o código errado, o que dificulta o tratamento do erro. Não altera valores. |
| Camada | API |
| Critério violado | Tabela de códigos de erro da documentação: `ITEM_INVALIDO` = "Um item não é um objeto com `produtoId` e `quantidade`" |
| Ambiente | https://verzel-store.qa-test-verzel-store.workers.dev/ — v2.3.0 |
| Cenário relacionado | CT-048 |

## Passos para reproduzir
```http
POST /api/carrinho/calcular
{"itens":[{"quantidade":1}]}
```
(o mesmo vale para `/api/pedidos`)

## Resultado esperado
`422` com `{"erro":{"codigo":"ITEM_INVALIDO", ...}}`, porque o item não tem `produtoId`.

## Resultado obtido
`422`, mas com o código **`PRODUTO_NAO_ENCONTRADO`** e a mensagem **"Produto undefined não encontrado."** (campo `itens[0].produtoId`). O texto "undefined" vaza um detalhe interno para a mensagem e o código de erro não é o previsto na documentação.

Comparação: um item que não é objeto (`null`, `"x"`, `[]`) retorna `ITEM_INVALIDO` corretamente. Com `produtoId` numérico (`4`) a resposta é "Produto 4 não encontrado." (aceitável).

## Observações
Só a API é afetada: a interface sempre envia `produtoId`. A severidade é baixa por ser uma mensagem/código de erro, sem efeito em valores. Se a equipe entender que "produtoId ausente" cai em `PRODUTO_NAO_ENCONTRADO`, a mensagem ainda deveria ser corrigida.
