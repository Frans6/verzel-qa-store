# BUG-003 — Cupom permanece aplicado após remover o último item pelo botão "Remover"

| Campo | Valor |
|-------|-------|
| Severidade | Baixa |
| Prioridade | Baixa |
| Impacto no negócio | O cliente recebe 10% de desconto num carrinho novo sem ter digitado o cupom. O valor é pequeno, mas gera preço diferente do esperado. |
| Camada | UI |
| Critério violado | Nenhum critério explícito; comportamento **inconsistente** entre duas ações equivalentes. Ver `docs/05-ambiguidades.md` (item 5) |
| Ambiente | https://verzel-store.qa-test-verzel-store.workers.dev/ — v2.3.0, Chromium 156 / Windows 11 |
| Cenário relacionado | CT-039 |

## Passos para reproduzir
1. Adicionar 1x **Mochila Urbana 20L** e aplicar o cupom `BEMVINDO10` no carrinho.
2. Clicar em **Remover** no único item (carrinho fica vazio).
3. Voltar à vitrine e adicionar 1x **Kit 3 Pares de Meias**.
4. Abrir o carrinho.

## Resultado esperado
Carrinho novo **sem** cupom aplicado (como acontece ao usar "Esvaziar carrinho").

## Resultado obtido
O cupom `BEMVINDO10` continua aplicado ao novo carrinho (desconto de R$ 2,99 sem o cliente ter digitado o cupom). Já o botão **Esvaziar carrinho** limpa o cupom.

## Observações
A documentação não define o que acontece com o cupom ao esvaziar o carrinho, então pode ser decisão de produto. Reporto como baixa severidade por causa da **inconsistência** entre as duas formas de esvaziar. Dado que o carrinho vive em `sessionStorage` (aba), o cupom também é guardado ali.
